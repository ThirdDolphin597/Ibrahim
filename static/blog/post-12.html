The LED Lightbox Project: January - April

The year kicked off with the LED lightbox project—a mandatory sophomore robotics assignment that taught me more about PCB design and manufacturing than I could have imagined.

From Breadboard to Final PCB

I started with a breadboard prototype, testing an ATMEGA32 microcontroller controlling an LED light strip via USB-C power. This rapid prototyping phase was crucial for identifying design flaws early.

Initial breadboard prototype for circuit testing

Next came the PCB design phase in Fusion 360. I had to model the ATMEGA32 from scratch, along with custom schematics for the USB-C power board and LED light strip. After careful trace routing and manufacturing through CNC milling, I had a professional PCB ready for soldering.

Precision trace routing for the custom PCB

Troubleshooting and Iteration

Like any real engineering project, I ran into issues. After soldering all components, the LED wouldn't light up initially. Through systematic troubleshooting with a multimeter, I discovered the light strip connector needed to be bent in a specific way to make contact. Eventually, I redesigned the PCB with software-controlled switching using digital I/O pins, which gave me much better control over the LED behavior.

The completed and tested PCB

Hall Effect Sensor Integration

To take the project further, I integrated a contactless hall effect sensor for activation. This replaced the mechanical switch with a magnetic trigger, allowing me to control the lightbox with a magnet placed near the housing.

3D Modeling and Manufacturing

The physical enclosure was where the project really came to life. I designed a box with a sliding tray system that holds all electronics magnetically. The tray contains the PCB, USB-C port, and toggle switch—all accessible by simply pulling it out.

Updated CAD model with hall effect sensor

Rounded base design with magnetic closure

Final Assembly and Laser Engraving

I 3D printed the enclosure and tray, milled and soldered the final PCB, and laser-cut the acrylic diffuser panel. The final lightbox features the Microsoft Edge logo laser-engraved on acrylic—a humorous touch to the otherwise professional project.

The Sumo Bot Project: April - June

After completing the lightbox, I shifted focus to an entirely different challenge—designing and building a competitive sumo bot robot. This project combines everything I learned from the lightbox with aggressive mechanical design and autonomous control strategies.

Project Overview

A sumo bot is a small autonomous robot designed to push opponents out of a circular ring during competition. The challenge is to maximize traction and pushing power while staying within strict weight and size constraints. This robot needs to detect the ring boundary, navigate autonomously, and deliver maximum force to push opponents out.

Chassis Design and Materials

I designed a symmetrical chassis that prioritizes low center of gravity and maximum surface contact. The body is 3D printed for precision and durability, engineered to protect all electronics inside. Strategic steel placement at the bottom of the chassis provides additional weight, creating the lowest possible center of gravity for stable pushing during matches.

Steel weight positioned at the bottom to lower the robot's center of gravity

Drivetrain and Traction

For maximum grip on the competition ring, I implemented a two-motor drivetrain with custom laser-cut wheels. The wheel design was an iterative process—I went through multiple cog configurations to find the optimal grip pattern on the timing pulleys.

One key challenge was heat from the laser cutter. When cutting thicker acrylic, the laser spent more time on the material, causing the cogs to melt and warp. After testing various materials and thicknesses, I discovered that 1/8-inch acrylic sheets with default laser cutter settings produced the most accurate wheels. The precision of 1/8-inch material meant the cogs grabbed the timing pulleys cleanly and reliably. To achieve the correct wheel width, I stacked two of these wheels together on each motor.

Strategic placement of the steel weight at the bottom of the chassis creates the lowest possible center of gravity, which is critical for stable pushing and resisting opponent attacks. Combined with the precision-cut wheels that grip the timing pulleys reliably, this design prioritizes stability and control.

I spent considerable time on the prototype build, 3D printing the motor mount tray and refining the wheel design to validate the mechanical fit. Once I confirmed everything fit properly, I moved on to integrating the electronics.

Motor Control and Code

My partner and I developed the control firmware for bidirectional motor control. Using light sensors to detect the white ring boundary, the robot autonomously navigates and responds to edge detection. The robot has four IR sensors positioned at each corner—front-left, front-right, back-left, and back-right—to detect the white boundary and keep the robot inside the ring.

IR light sensors detect the white ring boundary to keep the robot in play

Here's the complete working code:

// --- Light Sensors (use numeric analog pins) ---
int sFL = 5;   // A5
int sFR = 0;   // A0
int sBL = 1;   // A1
int sBR = 2;   // A2

#define spin 4000
#define straight 1000

// --- Thresholds
int thFL = 300;   // front-left
int thFR = 200;   // front-right
int thBL = 100;   // back-left
int thBR = 100;   // back-right

void setup() {
  // Motor pins
  pinMode(6, OUTPUT);   // Motor A PWM
  pinMode(9, OUTPUT);   // Motor A DIR
  pinMode(10, OUTPUT);  // Motor B PWM
  pinMode(11, OUTPUT);  // Motor B DIR
  
  Serial.begin(9600);
}

void loop() {
  // Read all 4 sensors
  int fl = analogRead(sFL);
  int fr = analogRead(sFR);
  int bl = analogRead(sBL);
  int br = analogRead(sBR);
  
  // Debug print
  Serial.print("FL: "); Serial.print(fl);
  Serial.print("  FR: "); Serial.print(fr);
  Serial.print("  BL: "); Serial.print(bl);
  Serial.print("  BR: "); Serial.println(br);
  
  // --- EDGE DETECTION ---
  if (fl < thFL) {        // front-left sees white
    back(straight);
    right(spin);
  }
  else if (fr < thFR) {   // front-right sees white
    back(straight);
    left(spin);
  }
  else if (bl < thBL) {   // back-left sees white
    forward(straight);
    right(spin);
  }
  else if (br < thBR) {   // back-right sees white
    forward(straight);
    left(spin);
  }
  else {
    forward(0);           // normal movement
  }
  
  delay(20);
}

// --- MOVEMENT FUNCTIONS ---
void forward(int wait) {
  digitalWrite(6, HIGH);
  digitalWrite(9, LOW);
  digitalWrite(10, LOW);
  digitalWrite(11, HIGH);
  delay(wait);
}

void right(int wait) {
  digitalWrite(6, HIGH);
  digitalWrite(9, LOW);
  digitalWrite(10, HIGH);
  digitalWrite(11, LOW);
  delay(wait);
}

void left(int wait) {
  digitalWrite(6, LOW);
  digitalWrite(9, HIGH);
  digitalWrite(10, LOW);
  digitalWrite(11, HIGH);
  delay(wait);
}

void back(int wait) {
  digitalWrite(6, LOW);
  digitalWrite(9, HIGH);
  digitalWrite(10, HIGH);
  digitalWrite(11, LOW);
  delay(wait);
}

The code reads all four sensors continuously. When any sensor detects the white boundary (analog value below threshold), the robot autonomously backs away and turns to stay in the ring.
